## AI safeguards
- New reviewedLedgerActions release flag defaults off until durable recovery across navigation/reload and authoritative authorization are proven. Existing confirmation implementation and tests retained behind flag. Cashbook and Transactions remain the operational write surfaces.
- Ask question again appends a fresh question and answer, preserving original response and avoiding unsupported in-place cloud updates. Production catalog confirms chat message read/insert/delete policies but no UPDATE policy; SQL grants alone do not authorize a row update.
- Server authenticates the token, verifies active membership via existing caller-scoped Supabase read and fails closed on empty, inactive or unavailable membership. No service-role key added. Bounded streaming prevents oversized incomplete responses; model never executes writes. Provider endpoint unit tests mock the network; real authenticated provider, MFA and RLS behavior remains unverified.
- Demo avoids real provider and cloud financial reads from LedgerMate; non-cloud accounts are prompted to sign in. Unrelated or concept-only queries send the latest question without earlier financial conversation history. Financial questions retain relevant existing history, with prior context redaction. No guarantee of complete PII redaction or injection resistance.
- Added tests for inactive membership, unavailable membership, repeat questions, demo isolation and unrelated history minimization. Distributed rate limiting, idempotent chat synchronization and full privacy review remain open.
