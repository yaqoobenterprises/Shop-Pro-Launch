# Shop Plus — Phase 05: accounts, money movement and financial reporting

## Accounts
- Ledger Ink neutral cards, compact balance summary, account identity and type labels, account actions above activity, explicit account drilldown into filtered Transactions. Account total uses exact integer aggregation and rejects unsafe values; negative balances remain negative. Positive allocation excludes zero and negative balances, as explicitly labeled. Loaded inactive count is not a complete historical account register.
- Preserve existing creation, rename, deactivation and transfer contracts. Add synchronous mutation lock, busy/disabled states, amount input decimal keyboard, failed form retention, stale-read request guard and retry/refresh. Account creation/transfer messaging respects the existing queued-offline return value. Demo/local operations are not presented as bank payments.
- UI permissions and ledger service guards use existing MANAGE_BUSINESS_CONFIG (owner) and ACCOUNT_TRANSFER (owner/manager) permission rules. No grant or deployed policy change. Source baseline migration includes owner-scoped account writes and permission-scoped transfer writes; live policies must still be verified.
- Historical migration 20261004003000_account_balances_and_postings.sql defines private.post_account_transfer() as an AFTER INSERT/UPDATE trigger, locks both accounts in ID order, posts TRANSFER_OUT and TRANSFER_IN in a single database transaction. Existing service upserts one transfer with operation ID and verifies duplicate result. 20261011000000_allow_account_overdraft_and_resilient_drafts.sql removed nonnegative balance restriction; this phase does not change it. Atomicity of the deployed database has not been independently proven. Offline queue acknowledgments, reactivation discovery, concurrent deactivation safety and lost-response retry still require dedicated integration testing. No new transfer type is invented in cashbook reports.

## Reports
- Existing reportAnalytics totals and business-date engine retained; cloud accounts require posted authoritative records. Local/demo reports explicitly qualify completeness. Applied filters and loaded record set must match before charts/tables/export are enabled. Failed reads show unavailable, not zero; retry action and separate export error state.
- More compact filter controls, applied-vs-draft indication, future/reversed date validation. Report chart bars use proportional values without minimum exaggeration, no decorative gradients. Exact values table, operating-result scale, clearer income/expense and category summaries.
- New account activity grouping by stable account ID, using existing financial reducer, and matching workbook sheet. This is recorded activity, not closing balances or transfer reconciliation. Current register pagination retained; print layout includes displayed page only and Excel includes full filtered register.
- Workbook terminology changed to Operating result (cashbook basis), Shop Plus branding, metadata includes source and filter scope. Valid three-letter currency code controls headers and Excel number format; PKR default preserves existing formatting. No change to historical amounts or currency conversion. No data migrations, live mutations or dependency additions.
